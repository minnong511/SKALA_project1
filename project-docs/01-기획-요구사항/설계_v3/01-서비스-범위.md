## 문제와 해결 방법

음료 조합이 여러 사이트와 개인 메모에 흩어져 있어 탐색과 재주문에 시간이 든다. 괴식도감은 브랜드별 조합을 하나의 도감 항목으로 관리하고, 사용자별 경험은 후기로 연결한다. 사용자는 설문 추천으로 후보를 좁히고, 도감에서 조합과 후기를 확인한 뒤 관심 메뉴를 저장한다.

## 핵심 흐름

회원가입 또는 로그인 → 최초 취향 설문 → 등록 메뉴 중 추천 확인 → 도감 상세 조회 → 북마크 또는 음료 경험 공유.

공유 흐름: 브랜드 선택 → 영수증 확인 → 조합과 후기 입력 → 등록 API의 LLM 동일 메뉴 판정 → 기존 메뉴에 후기 연결 또는 새 메뉴와 첫 후기 등록 → 메뉴 상세 조회.

실패 흐름: 입력 오류는 같은 화면에서 수정한다. 추천 실패 시 저장된 설문을 유지하고 도감으로 이동할 수 있다. 중복 메뉴는 기존 메뉴의 후기 작성으로 연결한다. 영수증 확인 실패 시 원인을 안내하고 재제출한다.

## MVP 범위

| 분류 | 포함 기능 | 범위 제한 |
| --- | --- | --- |
| 계정 | 이메일 가입과 로그인, 구글 로그인과 기존 계정 연결, 로그아웃 | 사용자와 관리자 공통 로그인, 관리자 공개 가입 없음 |
| 취향 | 5개 설문 응답 저장과 갱신 | 과거 설문 이력 저장 없음 |
| 추천 | 설문 추천 1개, 홈 추천, 메시지 기반 추천 | DB에 존재하는 메뉴만 추천, 새 레시피 생성 없음 |
| 도감 | 카테고리와 정렬, 상세, 후기 목록 | 별도 검색 엔진 없음 |
| 기록 | 북마크와 해제, 개인 페이지, 본인 후기 삭제 | 관심 메뉴는 북마크, 경험은 후기 |
| 공유 | 영수증 확인, 등록 내부 LLM 자동 판정, 조합과 후기 통합 등록, 기존 메뉴 후기 | 이미지 최대 5장 |
| 관리 | 메뉴 조회와 등급 변경, 메뉴 삭제, 브랜드 추가와 삭제 | 추가 관리 기능 없음 |

구글 로그인, 홈 추천, 챗봇, 관리자 기능은 기존 기술서에 포함된 기능이다. 기간이 부족할 경우 제외할 후보이지만 이번 문서에서는 임의로 제외하지 않는다. 제공 일정과 우선순위 조정은 [확인 필요].

## 이번 프로젝트에서 하지 않는 것

- AI의 새로운 음료 레시피 생성
- 기본 음료의 전체 재료 관리와 재료 변경 전후 추적, 관리자 재료 검토
- 별도 동일 메뉴 확인 API와 사용자 후보 선택 단계
- 매장 위치 검색, 지점 관리, 실시간 주문 가능 여부 확인
- 결제, 주문, 배송
- 댓글, 좋아요, 팔로우, 알림, 별도 공유 링크 생성 기능
- 후기 수정, 일반 사용자의 공용 메뉴 삭제, 메뉴 레시피 수정
- 장기 챗봇 기억, 추천 결과 및 영수증 원본의 영구 저장
- 마이크로서비스, 메시지 큐, 별도 캐시 서버

## 현재 v2에서 결정한 규칙

| 항목 | 적용 규칙 |
| --- | --- |
| 동일 메뉴 판정 | 등록 API 내부 LLM이 같은 브랜드의 기존 메뉴 ID 또는 null 반환. 서버가 ID를 검증한 후 자동 연결 |
| 오류 처리 | LLM 실패와 잘못된 출력은 등록 실패. 오류를 null로 간주해 메뉴를 생성하지 않음 |
| 메뉴 평점 | 사용자별 현재 후기 평균을 구한 뒤 그 평균들을 다시 평균냄 |
| 추가 재료 | 추가한 재료와 수량만 관리. 정량 표현 없는 수량은 NULL 허용 |
| 추천 범위 | 등록된 추가 재료에서 제외 조건 확인. 기본 음료 전체 성분은 주문 시 사용자가 확인 |
| 후기 삭제 | 본인 후기와 이미지 정리, 남은 후기 기준으로 평점 재계산 |
| 대표 이미지 | 해당 사진 삭제 시 주소를 NULL로 비우고 기본 이미지 표시. 다른 사진으로 교체하지 않음 |
| 입력 검증 | 평점, 이미지 수, 허용 값과 필수값은 API 검증. DB는 PK, FK, 중복 금지 제약 유지 |
| 동시 등록 | LLM 자동 판정을 적용하며 같은 신규 조합의 동시 생성 방지는 후속 개선 과제 |

## ID 체계


- 기능 요구사항: REQ-FUNC-001부터 순차 부여
- 비기능 요구사항: REQ-NFN-001부터 순차 부여
- 화면: SCR-AUTH-001 등 영역별 고정 ID
- API: OpenAPI operationId와 Method + Path
- DB: PostgreSQL 소문자 복수형 테이블명
- 인수 조건: AC-화면영역-번호

## 1단계 자체 검토

현재 v2의 1.5절, 2.2절, 4.2절, 5장과 6.1절을 기준으로 범위를 맞췄다. 등록 내부 LLM 판정, 사용자별 평균, 추가 재료만 관리하는 범위와 기본 이미지 표시를 적용한다. 확인되지 않은 구현 수치는 별도 제안으로 표시했다.
