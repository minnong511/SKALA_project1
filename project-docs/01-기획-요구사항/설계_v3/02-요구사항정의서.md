# 2단계. 요구사항정의서

작성자: 7반 이민형 | 버전: 0.3.1 | 기준: 현재 프로젝트 기술서 초안_v2.md

## 1. 프로젝트 기본 정보

프로젝트명: 괴식도감. Vue, Spring Boot, PostgreSQL. 기능은 계정, 취향과 추천, 도감, 공유와 기록, 관리로 구분한다. ID 체계와 확정 범위, 구현 제안은 [1단계](01-서비스-범위.md)를 따른다.

## 2. 서비스 개요

흩어진 카페 음료 조합을 모아 취향에 맞게 찾고, 경험을 후기로 공유한다. 로그인 → 설문 → 추천 → 상세 조회 → 북마크 또는 후기 등록이 핵심 흐름이다. 새 레시피 생성과 기본 음료 전체 재료 관리 등 제외 범위는 1단계를 따른다.

## 3. Actor

## 7. 비즈니스 규칙

- LLM 동일 메뉴 판정은 통합 등록 요청 내부에서 실행한다. 사용자에게 후보 선택을 요구하지 않는다.
- 서버가 비교 대상의 ID를 검증하며, 정상 null인 경우에만 새 메뉴를 생성한다.
- 메뉴 평점은 각 사용자의 현재 후기 평균을 다시 평균낸다. 후기가 남지 않은 사용자는 집계에서 제외한다.
- 추가 재료만 제외 조건과 비교하며 다음 문구를 표시한다: 기본 음료의 전체 성분은 주문 시 직접 확인하세요. 등록된 추가 재료 정보만 비교하며, 정보가 없다는 이유로 해당 성분이 없다고 판단하지 않습니다.
- 본인 후기 삭제 시 이미지와 후기를 정리하고, 대표 사진이면 주소를 NULL로 비운다.
- 평점 범위, 이미지 수, action 및 필수 입력은 API에서 검사한다. DB는 PK, FK와 UNIQUE를 유지한다.
- 영수증 인증 상태는 사용자와 브랜드에 연결하며 등록 성공 시 한 번만 소비한다.
- 중복 조합 동시 등록의 완전 방지는 후속 과제이며 보장된 기능으로 표기하지 않는다.

## 자체 검토

18개 기능 요구사항의 ID를 유지했다. REQ-FUNC-011은 별도 API가 아닌 등록 API 내부 처리로 재정의했다. 개인 페이지의 계정 조회와 로그아웃을 REQ-FUNC-001의 화면 연결에 포함했다.
